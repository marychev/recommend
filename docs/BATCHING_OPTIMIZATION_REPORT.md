# 📊 Отчет: Оптимизация POST запросов для ClickHouse через батчинг

**Дата:** 17 декабря 2025  
**Задача:** Оптимизация POST запросов для ClickHouse путем внедрения батчинга INSERT операций

---

## 🎯 Цель оптимизации

Оптимизировать POST запросы для ClickHouse, заменив одиночные INSERT операции на батчинг для повышения производительности и снижения нагрузки на базу данных.

---

## 📋 Проблема

### До оптимизации:
- ❌ Каждый POST запрос (`/users`, `/tracks`, `/events`) выполнял отдельный INSERT в ClickHouse
- ❌ При высокой нагрузке (100+ запросов/сек) создавалось 100+ отдельных INSERT запросов
- ❌ Высокая нагрузка на ClickHouse из-за частых операций записи
- ❌ Низкая эффективность при обработке большого количества запросов

### Метрики до оптимизации:
- **POST /users**: Среднее время ответа ~677ms (p95: 1162ms)
- **POST /tracks**: Среднее время ответа ~684ms (p95: 1184ms)  
- **POST /events**: Среднее время ответа ~483ms (p95: 800ms)
- **RPS**: ~17.92 запросов/сек

---

## ✅ Реализованное решение

### Архитектура батчинга

Реализован механизм батчинга на уровне `ClickHouseClient`:

```
POST /users → save_user() → save_user_buffered()
  ↓
Буфер users[] (до 100 записей)
  ↓
Автоматический flush каждые 5 сек или при 100 записях
  ↓
Батч INSERT в ClickHouse (1 запрос вместо 100)
```

### Компоненты реализации

#### 1. Буферы для батчинга

```python
# app/db/clickhouse.py
self._insert_buffer: Dict[str, deque] = {
    'users': deque(),
    'tracks': deque(),
    'user_track_interactions': deque(),
}
```

- **Размер батча**: 100 записей
- **Интервал flush**: 5 секунд
- **Тип данных**: `deque` для эффективной работы с очередью

#### 2. Методы батчинга

**`save_user_buffered()`** - сохранение пользователя:
- Генерирует ID сразу (для быстрого ответа клиенту)
- Добавляет запись в буфер `users[]`
- Запускает flush при достижении 100 записей

**`save_track_buffered()`** - сохранение трека:
- Генерирует ID сразу
- Добавляет запись в буфер `tracks[]`
- Запускает flush при достижении 100 записей

**`save_event_buffered()`** - сохранение события:
- Добавляет запись в буфер `user_track_interactions[]`
- Запускает flush при достижении 100 записей

#### 3. Автоматический flush

**По размеру:**
- При достижении 100 записей в буфере автоматически запускается flush
- Не блокирует основной поток (используется `asyncio.create_task`)

**По времени:**
- Периодический flush каждые 5 секунд
- Запускается при старте приложения через `lifespan`
- Останавливается при shutdown с полным сбросом всех буферов

**При остановке:**
- Все буферы автоматически сбрасываются перед остановкой приложения
- Гарантирует сохранение всех данных

#### 4. Интеграция в lifespan

```python
# app/utils/lifespan.py

# Startup
if clickhouse_connected:
    clickhouse = get_clickhouse_client()
    await clickhouse.start_periodic_flush()
    logger.info("Периодический flush буферов ClickHouse запущен")

# Shutdown
if clickhouse_connected:
    clickhouse = get_clickhouse_client()
    await clickhouse.stop_periodic_flush()
    logger.info("Периодический flush буферов ClickHouse остановлен")
```

## 🔧 Технические детали

### Структура буферов

```python
class ClickHouseClient:
    def __init__(self):
        # Буферы для батчинга INSERT запросов
        self._insert_buffer: Dict[str, deque] = {
            'users': deque(),
            'tracks': deque(),
            'user_track_interactions': deque(),
        }
        self._buffer_size = 100  # Размер батча
        self._flush_interval = 5.0  # Интервал автоматического flush
        self._flush_task: Optional[asyncio.Task] = None
        self._flush_lock = asyncio.Lock()  # Защита от race conditions
        self._running = False
```

### Метод flush буфера

```python
async def _flush_buffer(self, table: str) -> None:
    """Сбросить буфер в ClickHouse для указанной таблицы"""
    async with self._flush_lock:
        buffer = self._insert_buffer[table]
        if not buffer:
            return
        
        # Берем все записи из буфера
        records = list(buffer)
        buffer.clear()
    
    # Выполняем батч INSERT
    await self.insert(table, records, column_names)
```

### Обработка ошибок

- При ошибке INSERT записи возвращаются обратно в буфер
- Логирование всех ошибок для мониторинга
- Graceful degradation: система продолжает работать даже при ошибках

## 🛡️ Надежность

### Защита от потери данных

1. **Блокировка при flush**: используется `asyncio.Lock()` для защиты от race conditions
2. **Возврат при ошибке**: при ошибке INSERT записи возвращаются в буфер
3. **Flush при shutdown**: все буферы сбрасываются при остановке приложения
4. **Логирование**: все операции логируются для мониторинга

### Обработка ошибок

```python
try:
    await self.insert(table, records, column_names)
except Exception as e:
    logger.error("Ошибка при flush буфера %s: %s", table, e)
    # Возвращаем записи обратно в буфер
    async with self._flush_lock:
        self._insert_buffer[table].extendleft(reversed(records))
```
