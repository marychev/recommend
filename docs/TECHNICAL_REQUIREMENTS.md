# Рекомендательная система

Cервис должен обеспечивать обработку и сохранение событий, поступающих от различных источников, с возможностью быстрого анализа данных.


## Технологический стек:

- ClickHouse: Для хранения и аналитики больших данных (column-oriented DBMS, подходит для OLAP-запросов на исторические данные взаимодействий).
- Kafka: Для стриминга событий (реального времени обработка пользовательских действий как потоков сообщений).
- Redis: Для очередей 
- Python: Для реализации бизнес-логики, потребителей/продюсеров Kafka, ML-моделей рекомендаций (используя библиотеки типа Pandas, Scikit-learn, Surprise или TensorFlow) и API для запросов рекомендаций. ML-based (collaborative filtering)



## Функциональные требования

### Сбор данных:

Прием событий от фронтенда  (например, JSON-сообщения: user_id, item_id, action_type, timestamp).
Интеграция с Kafka для асинхронной обработки.



### Генерация рекомендаций:

Алгоритмы: Collaborative Filtering (user-based/item-based), Content-Based Filtering или гибридный подход.
Запрос рекомендаций через REST API (Python FastAPI), который querying ClickHouse и применяет модель.


### Мониторинг и логирование:

Использование Prometheus/Grafana для мониторинга Kafka и ClickHouse.
Логи в ELK-стеке (опционально, но рекомендуется).


### Интеграции:

API для внешних систем (например, интеграция с веб-сервером для показа рекомендаций).



## Нефункциональные требования

Тестирование: Unit-тесты (Pytest), интеграционные тесты для Kafka-ClickHouse, нагрузочное тестирование.
