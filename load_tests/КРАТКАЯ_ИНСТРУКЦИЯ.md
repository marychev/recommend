### 1. Как написать k6 тест с несколькими запросами?

✅ **Готово!** Создан файл `k6_full_user_scenario_test.js`

Тест включает три последовательных запроса:
1. **Авторизация** → получение токена
2. **Получение пользователя** → используя токен
3. **Получение рекомендаций** → используя токен

```javascript
export default function () {
  // 1. Авторизация
  const authResponse = http.post(`${BASE_URL}/api/v1/auth/login`, ...);
  const token = JSON.parse(authResponse.body).access_token;
  
  // 2. Получение пользователя
  const getUserResponse = http.get(
    `${BASE_URL}/api/v1/users/${userId}`,
    { headers: { 'Authorization': `Bearer ${token}` }}
  );
  
  // 3. Получение рекомендаций
  const recResponse = http.post(
    `${BASE_URL}/api/v1/recommendations`,
    payload,
    { headers: { 'Authorization': `Bearer ${token}` }}
  );
}
```

### 2. Как измерить МАКСИМАЛЬНОЕ количество пользователей?

✅ **Реализовано через 3 сценария:**

#### а) **Stress Test** - постепенное увеличение
```javascript
stress_test: {
  stages: [
    { duration: '2m', target: 100 },  // До 100 VU
    { duration: '2m', target: 150 },  // До 150 VU
    { duration: '2m', target: 200 },  // До 200 VU
  ]
}
```

#### б) **Spike Test** - резкий скачок
```javascript
spike_test: {
  stages: [
    { duration: '30s', target: 300 },  // Резко до 300!
    { duration: '2m', target: 300 },   // Удержание
  ]
}
```

#### в) **Breakpoint Test** - увеличение до отказа
```javascript
breakpoint_test: {
  executor: 'ramping-arrival-rate',
  stages: [
    { duration: '2m', target: 500 },  // До 500 req/s
  ]
}
```

**Результат:** В отчете указывается максимальное количество VU, при котором Success Rate > 70%

### 3. Как измерить ОПТИМАЛЬНОЕ количество пользователей?

✅ **Реализовано через Load Test:**

```javascript
load_test: {
  stages: [
    { duration: '2m', target: 20 },
    { duration: '5m', target: 20 },  // Долгое удержание
    { duration: '2m', target: 50 },
    { duration: '5m', target: 50 },  // Долгое удержание
  ]
}
```

**Критерии оптимальной нагрузки:**
- ✅ Success Rate > 95%
- ✅ Среднее время ответа < 3 секунды
- ✅ P95 < 5 секунд
- ✅ Error Rate < 5%

**Результат:** В отчете указывается оптимальное количество VU

### 4. Как измерить объем данных в запросе?

✅ **Реализовано через кастомные метрики:**

```javascript
// Метрики размера данных
const authRequestSize = new Trend('auth_request_size_bytes', true);
const authResponseSize = new Trend('auth_response_size_bytes', true);
const totalDataTransferred = new Trend('total_data_transferred_bytes', true);

// Измерение размера
function getByteSize(str) {
  return new Blob([str]).size;
}

// В коде теста
const requestSize = getByteSize(payload);
authRequestSize.add(requestSize);

const responseSize = getByteSize(response.body);
authResponseSize.add(responseSize);
```

## 📈 Интерпретация Результатов

### Определение Оптимального Количества

Смотрите на **Load Test** (20-50 VU):

✅ **Если Success Rate > 95% при 50 VU** → Оптимум = 50 VU
✅ **Если Success Rate < 95% при 50 VU** → Оптимум = 20-30 VU

### Определение Максимального Количества

Смотрите на **Stress Test** (100-200 VU) и **Spike Test** (300 VU):

⚠️ **Где Success Rate падает ниже 70%** → это максимум
⚠️ **Где ошибок > 30%** → система не справляется

### Пример:
```
Load Test (50 VU):     Success Rate = 98% ✅ → Оптимум: 50 VU
Stress Test (150 VU):  Success Rate = 85% ⚠️  → Работает, но не оптимально
Stress Test (200 VU):  Success Rate = 65% ❌ → Максимум: ~180 VU
Spike Test (300 VU):   Success Rate = 45% ❌ → Полный отказ
```

**Вывод:**
- **Оптимально:** 50 VU (Success Rate > 95%)
- **Максимально:** 180 VU (Success Rate > 70%)

## ⚠️ Важные Замечания

1. **Адаптируйте под свой API**
   - Измените endpoints в тесте
   - Обновите логику авторизации
   - Настройте payload

2. **Начинайте с малого**
   - Сначала запустите `k6_quick_test.js`
   - Убедитесь что все работает
   - Потом запускайте полный тест

3. **Мониторьте сервер**
   - Следите за CPU/RAM
   - Проверяйте логи API
   - Мониторьте базу данных

4. **Настройте thresholds**
   - Измените пороги под свои требования
   - В файле `options.thresholds`

## 🆘 Проблемы и Решения

### Проблема: Все запросы падают с ошибкой
```bash
# Проверьте что API запущено
curl http://localhost:8000/health

# Укажите правильный URL
k6 run --env API_URL=http://localhost:8000 load_tests/k6_quick_test.js
```

### Проблема: Авторизация не работает
- Проверьте endpoint `/api/v1/auth/login`
- Измените логику в коде теста
- Используйте свои credentials

### Проблема: Тест слишком долгий
```bash
# Используйте быстрый тест
k6 run load_tests/k6_quick_test.js

# Или укажите короткую длительность
k6 run --vus 10 --duration 1m load_tests/k6_quick_test.js
```
