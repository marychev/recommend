# K6 Комплексный Тест: Полный Пользовательский Сценарий

## 📋 Описание

Этот тест имитирует полный пользовательский сценарий работы с API:

1. **Авторизация** - получение токена доступа
2. **Получение данных пользователя** - запрос профиля
3. **Получение рекомендаций** - основная функциональность

## 🎯 Цели Теста

Тест измеряет три ключевых параметра:

### 1️⃣ Максимальное Количество Пользователей
**Определяется через:**
- **Spike Test** - резкий скачок до 300 VU
- **Stress Test** - постепенное увеличение до 200 VU
- **Breakpoint Test** - увеличение RPS до точки отказа

**Критерий:** Максимальное количество виртуальных пользователей, при котором Success Rate > 70%

### 2️⃣ Оптимальное Количество Пользователей
**Определяется через:**
- **Load Test** - тестирование при 20-50 VU с длительным удержанием

**Критерий:** 
- Success Rate > 95%
- Среднее время ответа < 3 секунды
- P95 < 5 секунд

### 3️⃣ Объем Данных в Запросах
**Измеряется:**
- Размер каждого запроса/ответа в байтах
- Суммарный объем данных за тест
- Средний объем на один сценарий

## 🚀 Запуск Теста

### Базовый запуск
```bash
k6 run load_tests/k6_full_user_scenario_test.js
```

### С указанием URL API
```bash
k6 run load_tests/k6_full_user_scenario_test.js --env API_URL=http://localhost:8000
```

### Запуск только определенного сценария
```bash
# Только Load Test
k6 run --include-scenario-in-results load_test load_tests/k6_full_user_scenario_test.js

# Только Stress Test
k6 run --include-scenario-in-results stress_test load_tests/k6_full_user_scenario_test.js

# Только Spike Test
k6 run --include-scenario-in-results spike_test load_tests/k6_full_user_scenario_test.js
```

### Быстрый тест (для отладки)
Отредактируйте файл и установите короткие duration для всех сценариев (например, 30s вместо минут).

## 📊 Структура Теста

### Временная Шкала (всего ~51 минута)

```
0:00 - 1:00   │ Warmup (5 VU)          │ Прогрев системы
1:00 - 17:00  │ Load Test (10-50 VU)   │ Определение оптимальной нагрузки
17:00 - 36:00 │ Stress Test (50-200 VU)│ Поиск точки отказа
36:00 - 41:00 │ Spike Test (10-300 VU) │ Проверка устойчивости к скачкам
41:00 - 51:00 │ Breakpoint Test        │ Увеличение до полного отказа
```

### Сценарии

#### 1. Warmup (Прогрев)
- **Длительность:** 1 минута
- **VU:** 5
- **Цель:** Прогреть кэши, инициализировать соединения

#### 2. Load Test (Нагрузочный тест)
- **Длительность:** 16 минут
- **VU:** 10 → 20 → 50 → 20
- **Цель:** Определить оптимальное количество пользователей

#### 3. Stress Test (Стресс-тест)
- **Длительность:** 19 минут
- **VU:** 50 → 100 → 150 → 200 → 0
- **Цель:** Найти точку, где система начинает деградировать

#### 4. Spike Test (Пиковый тест)
- **Длительность:** 5 минут
- **VU:** 10 → 300 (резко!) → 10
- **Цель:** Проверить устойчивость к резким скачкам нагрузки

#### 5. Breakpoint Test (Тест точки отказа)
- **Длительность:** 10 минут
- **RPS:** 50 → 100 → 200 → 300 → 400 → 500
- **Цель:** Найти абсолютный максимум системы

## 📈 Метрики

### Основные Метрики

| Метрика | Описание | Threshold |
|---------|----------|-----------|
| `auth_duration` | Время авторизации | P95 < 500ms, Avg < 300ms |
| `get_user_duration` | Время получения пользователя | P95 < 1000ms, Avg < 500ms |
| `get_recommendations_duration` | Время получения рекомендаций | P95 < 3000ms, Avg < 2000ms |
| `full_scenario_duration` | Время полного сценария | P95 < 5000ms, Avg < 3000ms |

### Метрики Успешности

| Метрика | Описание | Threshold |
|---------|----------|-----------|
| `auth_success_rate` | % успешных авторизаций | > 95% |
| `get_user_success_rate` | % успешных запросов пользователя | > 95% |
| `recommendations_success_rate` | % успешных рекомендаций | > 95% |
| `scenario_success_rate` | % успешных сценариев | > 90% |

### Метрики Данных

| Метрика | Описание |
|---------|----------|
| `auth_request_size_bytes` | Размер запроса авторизации |
| `auth_response_size_bytes` | Размер ответа авторизации |
| `get_user_response_size_bytes` | Размер ответа с данными пользователя |
| `recommendations_request_size_bytes` | Размер запроса рекомендаций |
| `recommendations_response_size_bytes` | Размер ответа с рекомендациями |
| `total_data_transferred_bytes` | Общий объем данных за сценарий |

## 🔍 Интерпретация Результатов

### Определение Оптимального Количества Пользователей

Смотрите на метрики во время **Load Test**:

✅ **Оптимальная нагрузка**, если:
- Success Rate > 95%
- Avg Response Time < 3s
- P95 < 5s
- Error Rate < 5%

### Определение Максимального Количества Пользователей

Смотрите на метрики во время **Stress Test** и **Spike Test**:

⚠️ **Максимальная нагрузка**, если:
- Success Rate > 70% (но < 95%)
- Avg Response Time < 5s
- Система все еще отвечает (не полный отказ)

❌ **Точка отказа**, если:
- Success Rate < 70%
- Error Rate > 30%
- Большое количество таймаутов

### Анализ Объема Данных

Посмотрите в разделе **💾 ОБЪЕМ ДАННЫХ**:

1. **Средний размер на сценарий** - сколько данных передается для одного пользователя
2. **Суммарный объем** - общий трафик за тест
3. **Скорость передачи** - пропускная способность сети

## 🛠️ Настройка Теста

### Изменение Продолжительности

Отредактируйте `options.scenarios` в файле:

```javascript
load_test: {
  executor: 'ramping-vus',
  startVUs: 10,
  stages: [
    { duration: '30s', target: 20 },  // Было '2m'
    { duration: '1m', target: 20 },   // Было '5m'
    // ...
  ],
}
```

### Изменение Количества VU

```javascript
stress_test: {
  stages: [
    { duration: '2m', target: 50 },   // Было 100
    { duration: '3m', target: 100 },  // Было 150
    // ...
  ],
}
```

### Настройка API Endpoints

Измените в коде функции `export default function()`:

```javascript
// Авторизация
const authResponse = http.post(
  `${BASE_URL}/api/v1/auth/login`,  // Ваш endpoint
  authPayload,
  authParams
);

// Получение пользователя
const getUserResponse = http.get(
  `${BASE_URL}/api/v1/users/${userId}`,  // Ваш endpoint
  getUserParams
);

// Рекомендации
const recommendationsResponse = http.post(
  `${BASE_URL}/api/v1/recommendations`,  // Ваш endpoint
  recommendationsPayload,
  recommendationsParams
);
```

## 🐛 Отладка

### Проблема: Все запросы падают

**Проверьте:**
1. API запущено и доступно
2. URL правильный (`--env API_URL=...`)
3. Endpoints существуют

### Проблема: Низкий Success Rate

**Возможные причины:**
1. API не справляется с нагрузкой
2. База данных перегружена
3. Нехватка ресурсов (CPU/RAM)
4. Проблемы с сетью

**Решение:**
1. Уменьшите количество VU
2. Оптимизируйте API
3. Масштабируйте инфраструктуру

### Проблема: Слишком долго выполняется

**Решение:**
1. Уменьшите duration в сценариях
2. Отключите ненужные сценарии
3. Запускайте только один сценарий
