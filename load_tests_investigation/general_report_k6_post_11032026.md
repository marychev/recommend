# 5. Выполненные оптимизации

## Исправленные баги:

1. **Баг в 7 k6-тестах**: все тесты вызывали `GET /recommendations/{id}` (не существует) вместо `POST /recommendations` с JSON body. Давало 100% ошибок 404. Исправлено.

2. **ClickHouse memory overallocation**: `max_memory_usage = 20GB` на системе с 5.8GB RAM. Исправлено на 2GB, `external_group_by/sort = 500MB`, `max_bytes_in_join = 1GB`. Файлы: `clickhouse-config/users.xml`, `app/routers/recommendations.py` (SETTINGS).

3. **`next_id()` — N+1 query**: каждый вызов `create_user/create_track` делал `SELECT ... ORDER BY ... DESC LIMIT 1` к ClickHouse. При 60+ VUs это убивало ClickHouse десятками конкурентных запросов. Исправлено: ClickHouse запрашивается только при первом вызове, далее используется Redis INCR. Файл: `app/db/clickhouse.py`.

4. **Popular tracks query timeout (30s+)**: один тяжёлый JOIN на 19M строк `user_track_interactions`. Исправлено на двухэтапный запрос (~1.3s): step 1 — top IDs без JOIN, step 2 — детали по ID. Файл: `app/routers/recommendations.py`.

5. **Отсутствие семафора**: тяжёлые collaborative filtering запросы запускались без ограничений. Добавлен `asyncio.Semaphore(3)`. Файл: `app/routers/recommendations.py`.

6. **Нет глобального кэша popular tracks**: каждый cold-start пользователь генерировал тяжёлый запрос. Добавлен глобальный Redis-кэш с TTL 10 мин. Файлы: `app/services/cache.py`, `app/routers/recommendations.py`.

7. **Client timeout 30s**: aiochclient timeout был меньше времени тяжёлых запросов. Увеличен до 60s. Файл: `app/db/clickhouse.py`.
