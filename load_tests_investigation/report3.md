## 🎯 ПОСТАНОВКА ЗАДАЧИ

### Цель этапа:
- **Повысить hit rate с 75-80% до 85-90%** через предварительный прогрев кэша
- **Устранить "холодные старты"** для активных пользователей
- **Обеспечить мгновенные ответы** для первых запросов активных пользователей

### Проблема "холодного старта":
Даже при оптимальном TTL и селективной инвалидации, первый запрос пользователя всегда приводит к MISS и требует обращения к ClickHouse (300-800ms). Для активных пользователей это создает негативный пользовательский опыт.

### Гипотеза:
Предварительная генерация и кэширование рекомендаций для активных пользователей позволит превратить их первые запросы из MISS в HIT, значительно улучшив производительность.

## 🔧 ТЕХНИЧЕСКАЯ РЕАЛИЗАЦИЯ

### 1. Сервис прогрева кэша (`app/services/cache_warmup.py`)

**Определение активных пользователей:**
```python
async def get_active_users(limit: int = 100) -> List[int]:
    """
    Получает список ID самых активных пользователей за последний месяц.
    """
    clickhouse = get_clickhouse_client()
    query = f"""
    SELECT user_id, count() as interactions_count
    FROM user_track_interactions
    WHERE timestamp >= now() - INTERVAL 30 DAY
    GROUP BY user_id
    ORDER BY interactions_count DESC
    LIMIT {limit}
    """
    result = await clickhouse.execute_raw(query)
    return [row[0] for row in result]
```

**Пакетный прогрев рекомендаций:**
```python
async def warmup_cache_for_active_users(num_users: int = 100):
    """
    Прогревает кэш для N самых активных пользователей.
    """
    logger.info(f"🔥 Запуск прогрева кэша для {num_users} активных пользователей...")
    active_users = await get_active_users(limit=num_users)
    
    tasks = [generate_and_cache_recommendations(user_id) for user_id in active_users]
    await asyncio.gather(*tasks)
    
    logger.info(f"✅ Прогрев кэша завершен для {len(active_users)} пользователей.")
```

## 📊 ЛОГИКА ПРОГРЕВА КЭША

### Критерии активных пользователей:

1. **Временной период:** Последние 30 дней
2. **Метрика активности:** Количество взаимодействий с треками
3. **Сортировка:** По убыванию активности
4. **Лимит:** Топ-50 до топ-100 пользователей

### Стратегия прогрева:

1. **Что прогревается:**
   - Стандартные рекомендации (top_n=10, exclude_listened=True)
   - Используются те же параметры, что и в реальных запросах

2. **Когда прогревается:**
   - По запросу через API
   - Потенциально по расписанию (будущая оптимизация)
   - После значительных изменений в данных

3. **Как прогревается:**
   - Параллельная обработка пользователей (asyncio.gather)
   - Использование существующей логики генерации рекомендаций
   - Автоматическое сохранение в кэш через стандартный механизм

### Математическая модель эффективности:

**Формула улучшения hit rate:**
```
Новый Hit Rate = Базовый Hit Rate + (% активных пользователей × Вероятность первого запроса)
```

**Пример расчета:**
- Базовый hit rate: 75%
- Активные пользователи: 20% от общего числа
- Вероятность первого запроса активного пользователя: 50%
- Улучшение: 20% × 50% = 10%
- **Итоговый hit rate: 75% + 10% = 85%**

| **Hit Rate** | 75-80% | 85-90% | **+10-15%** |

### Сценарии использования:

1. **Активный пользователь заходит утром:**
   - Без прогрева: MISS → 500ms ожидания
   - С прогревом: HIT → 3ms ответ ✨

2. **Пиковая нагрузка:**
   - Без прогрева: Много MISS → перегрузка ClickHouse
   - С прогревом: Больше HIT → стабильная работа

3. **Новые пользователи:**
   - Прогрев не влияет (они не активные)
   - Базовая логика кэширования работает как раньше
